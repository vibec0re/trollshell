# trollshell v0.2.6 robustness & polish

**Status:** design
**Date:** 2026-04-26
**Author:** Claude (with annika)
**Predecessors:** `2026-04-25-trollshell-v0.2.1-polish-design.md`, `2026-04-25-network-panel-redesign-design.md`, `2026-04-26-osd-redesign-design.md`, `2026-04-26-stats-page-redesign-design.md`.

## Goal

Three independent robustness/polish sub-features bundled as v0.2.6. (A) Notifications mount on every monitor and route to the focused output, mirroring the v0.2.3 OSD pattern. (B) BlueZ + iwd shared command connections detect closed peers and auto-reopen so trollshell survives `systemctl restart bluetooth` / `iwd` without itself restarting. (C) Network panel's Primary expander surfaces IPv4/IPv6 prefix lengths on address rows, and the "No connection" state hides the expander entirely behind a non-activatable placeholder row.

## Scope

### In scope

**Sub-feature A — Multi-monitor notifications (`trollshell/src/widgets/notifications.rs`):**

- Replace `TOAST_WINDOW: RefCell<Option<gtk::Window>>` with `TOAST_WINDOWS: RefCell<HashMap<String, ToastView>>` keyed by `Monitor.connector()`.
- Add `FOCUSED_OUTPUT: RefCell<Option<String>>` cell + `SUBS_INSTALLED: Cell<bool>` first-call guard, mirroring v0.2.3 OSD.
- Extract widget construction into `build_toast_view(monitor: &Monitor) -> ToastView`. Move signal wiring into `install_subscriptions()`. `install(&Monitor)` becomes per-monitor, calls `install_subscriptions` once.
- Subscriptions: `niri::focused_output()` writes `FOCUSED_OUTPUT`; the existing combined `(notifications, dnd, muted)` signal calls `route_emission`. `route_emission` picks the target view (focused output, fallback to first mounted) and runs the existing card-add/remove + overflow logic against THAT view's per-window state (`card_map`, `overflow_card`, `suppressed_during_dnd`).
- `main.rs` swap: move `widgets::notifications::install` from the primary-only block into the per-monitor loop alongside `osd::install`. `prompt` and `polkit_dialog` stay primary-only.

**Sub-feature B — Service reconnect (`crates/hytte-services/src/{bluetooth,wifi}.rs`):**

- Replace `static CMD_CONN: OnceCell<Connection>` with `static CMD_CONN: tokio::sync::Mutex<Option<Connection>>` in both files.
- `cmd_conn()` returns `Result<Connection>` (owned clone of the Arc-backed `zbus::Connection`). Body: `lock().await`, if `is_none() || is_closed()` reopen via `Connection::system().await`, store, return clone.
- All existing `do_*_call` helpers continue to compile unchanged (they use `let conn = cmd_conn().await?;` then `conn.call_method(...).await`; the only delta is `conn` is owned instead of `&'static`, both expose the same method API).
- Listen loops untouched (already retry with backoff).
- `systemd` service untouched (per-iteration connection in `listen()`, already reconnect-safe).

**Sub-feature C — Network panel polish:**

- (`crates/hytte-services/src/networkd.rs`) — `Link.addresses` becomes `Vec<LinkAddress>` where `pub struct LinkAddress { pub addr: IpAddr, pub prefix_len: u8 }`. `parse_describe` populates the new struct from existing `DescribeAddress.prefix_length`. Existing `parses_describe_json_minimal` test asserts the new shape.
- (`trollshell/src/widgets/pages.rs::build_primary_expander`) — IPv4/IPv6 address rows render `192.168.1.42/24` instead of `192.168.1.42` (and analogously for v6). Strips the existing `"No connection"` title-fallback.
- New `build_no_connection_placeholder_row` adds a non-activatable `AdwActionRow` to the Connection group, visible only when `networkd::primary().is_none()`. The Primary expander gains a `set_visible` bind on `primary().is_some()`. Mutually exclusive visibility.

### Out of scope

- OSD hotplug handling on newly-connected monitors (deferred to v0.2.7).
- Niri events (`WorkspaceUrgencyChanged`, `KeyboardLayoutSwitched`) — still tagged v0.3+.
- Auto-retry of mid-call dbus failures on `ConnectionClosed` — user re-clicks; documented as accepted trade-off.
- MAC address row on Primary expander.
- Multi-monitor migration of `prompt` and `polkit_dialog` — security gates with modal/keyboard-grabbing semantics.
- Listen-loop reconnect changes (already correct).
- Per-interface address rendering on All-links expander.
- IPv6 prefix on the gateway row (gateways are single-address; no prefix).

### Success criteria

- `cargo clippy --workspace --all-targets -- -D warnings` clean.
- `cargo test --workspace` green; `parses_describe_json_minimal` updated for the new `LinkAddress` shape.
- Manual:
  - **A:** On a 2-monitor setup, focus monitor A → `notify-send hello world` → toast appears on A only. Focus B → `notify-send second` → toast appears on B only. Burst (≥7 notifications) renders the `+N more` overflow card on the focused monitor's view as before.
  - **B:** `sudo systemctl restart bluetooth` while trollshell is running → click Scan in BT drawer → discovery starts within ~1 second. `sudo systemctl restart iwd` while running → click Scan in Wi-Fi → networks repopulate. Neither requires trollshell restart.
  - **C:** Network drawer's Primary expander shows e.g. `192.168.1.42/24` on the IPv4 row and `2001:db8::1/64` on the IPv6 row. Disconnect from network → Primary expander disappears; "No connection" placeholder row appears in its place. Reconnect → expander reappears, placeholder hides.

## §1 — Multi-monitor notifications

### Current shape

`widgets/notifications.rs` (~330 lines) builds a single layer-shell window pinned top-right. State (`card_map`, `overflow_card`, `suppressed_during_dnd`) lives in closure-captured RefCells inside a single `install` body. Subscriptions are wired inside `install`.

### New shape

```rust
struct ToastView {
    window: gtk::Window,
    vbox: gtk::Box,
    card_map: RefCell<HashMap<u32, gtk::Widget>>,
    overflow_card: RefCell<Option<gtk::Widget>>,
    suppressed_during_dnd: RefCell<HashSet<u32>>,
}

thread_local! {
    static TOAST_WINDOWS: RefCell<HashMap<String, ToastView>> =
        RefCell::new(HashMap::new());
    static FOCUSED_OUTPUT: RefCell<Option<String>> = const { RefCell::new(None) };
    static SUBS_INSTALLED: Cell<bool> = const { Cell::new(false) };
}
```

### `install`, `build_toast_view`, `install_subscriptions`

```rust
pub fn install(monitor: &Monitor) {
    let connector = match monitor.connector() {
        Some(c) if !c.is_empty() => c,
        _ => {
            tracing::debug!("notifications::install: monitor has no connector; skipping");
            return;
        }
    };
    let view = build_toast_view(monitor);
    TOAST_WINDOWS.with(|map| map.borrow_mut().insert(connector, view));
    if !SUBS_INSTALLED.with(Cell::get) {
        SUBS_INSTALLED.with(|c| c.set(true));
        install_subscriptions();
    }
}

fn build_toast_view(monitor: &Monitor) -> ToastView {
    // Existing widget construction (layer_window builder, vbox, css class)
    // moved here, returning a ToastView with empty per-window RefCells.
    // No signal wiring.
}

fn install_subscriptions() {
    // niri::focused_output() → FOCUSED_OUTPUT
    glib::MainContext::default().spawn_local(
        niri::focused_output().for_each(|out| {
            FOCUSED_OUTPUT.with(|c| *c.borrow_mut() = out);
            std::future::ready(())
        }),
    );

    // Existing combined (notifications, dnd, muted) signal — but the
    // for_each closure now calls route_emission instead of mutating
    // the single-window state.
    let toast_signal = map_ref! { ... };  // unchanged
    glib::MainContext::default().spawn_local(
        toast_signal.for_each(|(notifs, dnd_on, muted)| {
            route_emission(&notifs, dnd_on, &muted);
            std::future::ready(())
        }),
    );
}
```

### `route_emission`

```rust
fn route_emission(
    notifs: &[Notification],
    dnd_on: bool,
    muted: &HashSet<String>,
) {
    let target_name = FOCUSED_OUTPUT.with(|c| c.borrow().clone());
    TOAST_WINDOWS.with(|map| {
        let map = map.borrow();
        if map.is_empty() {
            return;
        }
        let view = target_name
            .as_ref()
            .and_then(|n| map.get(n))
            .or_else(|| map.values().next());
        if let Some(view) = view {
            apply_emission(view, notifs, dnd_on, muted);
        }
    });
}

fn apply_emission(
    view: &ToastView,
    notifs: &[Notification],
    dnd_on: bool,
    muted: &HashSet<String>,
) {
    // The existing for_each body — DND/mute filter, suppressed_during_dnd
    // bookkeeping, partition into critical/non-critical, head/tail,
    // card_map add/remove, overflow_card management, window.set_visible.
    // The only difference: state mutation goes through view.card_map.borrow_mut(),
    // view.overflow_card.borrow_mut(), view.suppressed_during_dnd.borrow_mut(),
    // and view.window / view.vbox.
}
```

### `main.rs` change

```rust
if let Some(primary) = app.monitors().first() {
    widgets::prompt::install(primary);
    widgets::polkit_dialog::install(primary);
}

for monitor in &app.monitors() {
    widgets::notifications::install(monitor);
    widgets::osd::install(monitor);
}
```

### Edge cases

- **Focus changes mid-toast:** an active toast continues its lifecycle on its original monitor. Two surfaces visible briefly. Acceptable; matches v0.2.3 OSD.
- **`Monitor.connector()` is None or empty:** skip with debug log.
- **`FOCUSED_OUTPUT` is None or unmapped:** route to `map.values().next()`. Notifications always land somewhere.
- **Per-view `suppressed_during_dnd`:** intentional — each notification only ever touches one view via routing, and the suppressed-during-dnd is a from-now-forward gate per the existing memory rule. Per-view scope is correct.
- **Per-view `overflow_card`:** also intentional. The "+N more" card is per-monitor. If the user pokes 7 notifications focused on A, then focuses B and pokes 3 more, A has its own overflow state and B has its own. Matches per-monitor display semantics.

## §2 — Service reconnect

### Current shape (both files)

```rust
static CMD_CONN: OnceCell<Connection> = OnceCell::const_new();

async fn cmd_conn() -> Result<&'static Connection> {
    CMD_CONN
        .get_or_try_init(|| async {
            Connection::system().await.context("…")
        })
        .await
}
```

`OnceCell` is set-once. After init, no path reopens.

### New shape

```rust
static CMD_CONN: tokio::sync::Mutex<Option<Connection>> =
    tokio::sync::Mutex::const_new(None);

async fn cmd_conn() -> Result<Connection> {
    let mut guard = CMD_CONN.lock().await;
    if guard.as_ref().is_none_or(zbus::Connection::is_closed) {
        let fresh = Connection::system()
            .await
            .context("open shared bluetooth command connection")?;
        *guard = Some(fresh);
    }
    Ok(guard
        .as_ref()
        .expect("just stored Some")
        .clone())
}
```

The error context message is bluetooth-specific in `bluetooth.rs` and mirrored ("open shared wifi command connection") in `wifi.rs`.

### Why the shape

- **`tokio::sync::Mutex`, not `std::sync::Mutex`** — we await inside the critical section (the `Connection::system().await` reopen). std mutex would deadlock or panic on async hold.
- **`Mutex::const_new(None)`** — `const fn` constructor. `static` initialization, no `OnceLock`-style indirection.
- **`is_none_or(zbus::Connection::is_closed)`** — handles both first-call (None) and reconnect (Some-but-closed) in one expression. `is_none_or` is stable since 1.82, workspace is 1.94.
- **Returns `Connection` (owned, Arc-clone)** — `zbus::Connection` is `Clone`-cheap. Each call site owns its clone for the duration of the dbus round-trip; the lock is released immediately after.
- **Single mutex hold time:** microseconds in steady state, ~10ms when reopening. Never held across the actual `call_method`.

### Failure modes

| Scenario                       | Behavior                                                                                                                                                                                 |
| ------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| First call ever                | Lock, see None, open + store, return clone.                                                                                                                                              |
| Steady-state                   | Lock, see Some+open, return clone.                                                                                                                                                       |
| Daemon restarted between calls | Lock, see Some+closed, reopen + store, return clone.                                                                                                                                     |
| Daemon restart mid-call        | The in-flight `call_method` errors with `ConnectionClosed`. Caller logs at warn. Next call sees closed, reopens. **User retries the click; one click is "lost" to the dead connection.** |
| Daemon down at startup         | First call's `Connection::system()` fails (no socket). User sees a warn log. Next call retries.                                                                                          |

### Call sites unchanged

In both files, every existing helper has the form:

```rust
async fn do_X(...) -> Result<()> {
    let conn = cmd_conn().await?;
    conn.call_method(...).await?;
    Ok(())
}
```

After the refactor, `conn` becomes `Connection` (owned) instead of `&'static Connection`. Both deref/expose the same `call_method` API. Zero changes to helper bodies.

### Listen loops + systemd untouched

Both `listen()` functions in `bluetooth.rs` and `wifi.rs` already retry on error with backoff (5s and 2s respectively). They open their own `Connection::system()` per iteration. The reconnect refactor doesn't touch them.

`crates/hytte-services/src/systemd.rs::listen()` opens a fresh connection per outer-loop iteration too. Already reconnect-safe by construction.

### Tests

- **Unit tests:** none practical. Reconnect requires a real bus + daemon to fake a restart.
- **Manual verification (deferred):** see §1 success criteria.

## §3 — Network panel polish

### §3a — IPv4/v6 prefix length

**Service-side:**

```rust
#[derive(Clone, Debug)]
pub struct LinkAddress {
    pub addr: IpAddr,
    pub prefix_len: u8,
}

#[derive(Clone, Debug, Default)]
pub struct Link {
    pub idx: i32,
    pub name: String,
    pub operational: OperationalState,
    pub addresses: Vec<LinkAddress>,
    pub gateway_v4: Option<Ipv4Addr>,
    pub gateway_v6: Option<Ipv6Addr>,
    pub routes: Vec<RouteSummary>,
}
```

`parse_describe` populates from existing `DescribeAddress.prefix_length`:

```rust
for a in raw.addresses {
    if let Some(addr) = bytes_to_ip(a.family, &a.address) {
        out.addresses.push(LinkAddress {
            addr,
            prefix_len: a.prefix_length,
        });
    }
}
```

Existing test `parses_describe_json_minimal` updated to assert:

```rust
assert_eq!(parsed.addresses.len(), 1);
assert_eq!(parsed.addresses[0].addr, IpAddr::V4(Ipv4Addr::new(192, 168, 1, 42)));
assert_eq!(parsed.addresses[0].prefix_len, 24);
```

**UI-side (`pages.rs::build_primary_expander`):**

The existing IPv4 address row's signal map:

```rust
link.addresses
    .iter()
    .filter_map(|ip| match ip {
        std::net::IpAddr::V4(v) => Some(v.to_string()),
        _ => None,
    })
    .collect::<Vec<_>>()
    .join(", ")
```

becomes:

```rust
link.addresses
    .iter()
    .filter_map(|a| match a.addr {
        std::net::IpAddr::V4(v) => Some(format!("{v}/{}", a.prefix_len)),
        _ => None,
    })
    .collect::<Vec<_>>()
    .join(", ")
```

IPv6 row mirrors the same change; the existing link-local filter (`is_unicast_link_local()`) and `(+N more)` collapse for multi-v6 stay in place.

### §3b — "No connection" hide-and-replace

Currently `build_primary_expander` (added in v0.2.2) sets the title to "No connection" via:

```rust
bind(
    networkd::primary().map(|p| match p {
        Some(link) => link.name,
        None => "No connection".to_string(),
    }),
    &expander,
    |w, name| w.set_title(&name),
);
```

**Strip the None-fallback** so the title bind reads:

```rust
bind(
    networkd::primary().map(|p| p.map_or(String::new(), |link| link.name)),
    &expander,
    |w, name| w.set_title(&name),
);
```

(When `primary` is None the title is empty, which doesn't matter because the expander itself is hidden.)

**Add visibility bind on the expander:**

```rust
bind(
    networkd::primary().map(|p| p.is_some()),
    &expander,
    gtk::prelude::WidgetExt::set_visible,
);
```

**Add new placeholder builder** in `pages.rs`:

```rust
fn build_no_connection_placeholder_row() -> adw::ActionRow {
    let row = adw::ActionRow::builder()
        .title("No connection")
        .activatable(false)
        .selectable(false)
        .build();
    row.set_subtitle("No primary network link");
    bind(
        networkd::primary().map(|p| p.is_none()),
        &row,
        gtk::prelude::WidgetExt::set_visible,
    );
    row
}
```

**Wire into `build_connection_group_v2`:**

```rust
group.add(&build_primary_expander());
group.add(&build_no_connection_placeholder_row());
group.add(&build_all_links_expander());
group.add(&build_dns_expander());
```

Visibility is mutually exclusive — exactly one of (Primary expander, placeholder row) is visible at a time, driven by the same `networkd::primary().is_some()` signal.

4. **B.1:** Replace `bluetooth.rs::CMD_CONN` shape; refactor `cmd_conn()`; verify call sites compile.

6. **C.1:** `networkd.rs` `LinkAddress` struct + parser update + test update.

8. **C.3:** `pages.rs` Primary expander hide-and-replace + new placeholder row.
